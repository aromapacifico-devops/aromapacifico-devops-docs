# Requirements validation and failure scenarios

This document is the T-07 design validation matrix. It maps the requirements that are present in this repository to components, failure scenarios, safe outcomes and verifiable documentary evidence. It does not claim that AWS resources are deployed, that a field trial passed, or that a recovery exercise was executed.

## 1. Status and evidence boundary

T-07 remains **PENDING**. GitHub Issue #64 is open and its T-02 dependency, Issue #59, is also open. The operational alarm document merged into `main` is useful design evidence, but it does not replace the open dependency or prove deployed alarms and response routes.

The original file named `Ejercicio-Junior-Senior-DevOps-AromaPacifico.pdf`, referenced by the Issues, is not present in this repository. The PDFs under `docs/design/` are application and brand designs, not the original case statement. Therefore this matrix uses only the repository's requirements reconciliation, architecture documents, contracts, schemas and current GitHub Issue state. A requirement that exists only in the unavailable PDF cannot be independently verified here.

Status values have the following meaning:

| Status | Meaning |
|---|---|
| `COVERED-DESIGN` | A repository document specifies the scenario and a safe expected result. It is not evidence of deployment or a field test. |
| `PARTIAL` | The design is present, but an assumption, contradiction, implementation gap or unexecuted environment check remains. |
| `BLOCKED` | Completion depends on open T-02 (#59), unavailable primary evidence, or another unresolved prerequisite. |
| `PENDING-EXECUTION` | A test procedure exists, but no measured environment or field result was found. |

## 7. Completion criteria for T-07

The documentary matrix and mandatory scenarios are present, but T-07 must remain open until all of the following are true:

1. T-02 (#59) is completed or its owners explicitly provide the final alarm routes and evidence; this matrix must then be reconciled with that result.
2. The original case PDF is supplied and every primary requirement is checked against this matrix, or the project formally identifies the repository reconciliation as the controlled primary source.
3. The EventBridge rule-DLQ implementation gap is tracked and its status is stated without claiming deployment.
4. Pending field, cloud-service, restore and redrive exercises are kept as pending until measured artifacts exist.
5. Any decision to change the merged retry count, timeouts, concurrency or publication pattern is made in its own reviewed change; the archived E4-10 branch is not merged as a shortcut.
